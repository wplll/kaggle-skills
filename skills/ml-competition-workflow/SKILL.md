# 机器学习比赛实验流程

让每轮实验回答一个会改变决策的问题。实现核验通过只说明实验可信，不说明值得继续投入。

## 从当前阶段接续

先读项目规则、当前最佳有效提交、数据划分、最近结果和用户的执行边界。已有证据足够时直接工作，不重复索取信息或从头审计。用户指定的模型、预算、数据范围和提交意图优先；发现限制使假设不可检验时，具体说明证据缺口，不擅自扩大范围。

按任务只读取需要的参考文件：

- 启动比赛、检查划分、全量数据或预训练来源：[data-and-validation.md](references/data-and-validation.md)。
- 开源/论文对照、方向选择、连续失败、训练实验：[experiment-decisions.md](references/experiment-decisions.md)。
- 打包、远端运行、提交报错、最终拟合及最终选模：[execution-and-submission.md](references/execution-and-submission.md)。
- 需要留下可接续记录时使用[working-records.md](references/working-records.md)，已有等价配置/日志不再复制建账。
- 做比赛复盘或需要理解流程动机时读取[biohub-lessons.md](references/biohub-lessons.md)。其中的阈值、模型和样本规模是案例，不是后续比赛默认配置。

## 先建立四项事实

1. **优化目标：**官方指标、合法预测格式、隐藏分布和资源约束；区分训练代理损失与最终计分。以主办方当前代码/说明为准，保留版本与差异。
2. **独立单位：**样本属于哪些患者、设备、地点、时间段、胚胎或其他共享来源；核验新增训练及预训练、伪标签、归一化、教师、集成的暴露。文件不重叠不代表来源独立。
3. **基线身份：**代码/配置/权重与精确提交版本绑定；成功运行、有效评分、最佳公榜和泛化证据分别记录。无法绑定的当前源码不能冒充历史高分版本。
4. **实际覆盖：**允许数据池、唯一枚举样本、实际消费样本、监督可用样本和重复曝光分别报告。固定步数只访问部分缓存时不能称作全量训练。

保留未确定项。来源缺失降低结论强度，不应无限阻止已有授权范围内的探索；未知来源的开发分不能包装成无偏验证。

## 选择下一轮前回答

- 最终错误主要在哪个环节？该错误是否在当前候选、可见特征和标签下可恢复？
- 拟议改动增加什么有效信息或改变什么决策机制？同一稀疏监督上的更大网络不自动增加可学习信息。
- 局部改变经过融合、阈值、求解、重连、过滤、量化等实际步骤后，会保留在哪里？设计一个低成本探针证明接入会起作用。
- 什么结果支持假设，什么结果会否定它？本轮之后是继续、转向、停止还是提交验证？

根据“可恢复收益、证据强度、信息增量、实现和运行成本”选择方向，不把一张长候选清单默认变成全部执行任务。用户明确要求串行执行多个实验时，保留约定队列与统一验证；执行前指出不成立的前提，失败隔离，不偷偷改变参数。

## 两层实验验收

**实现层：**核验接口、有效掩码、梯度/冻结、坐标/单位、缓存来源、恢复状态和训练—推理一致性，只做与改动有关的检查。零初始化一致不能替代非零路径检查。

**研究层：**使用官方最终指标及分组结果，解释代理指标与最终结果的差异。数值复现容差不是有效收益门槛；偏小且重复使用的开发集无法靠更严格容差变成泛化验证。若多项指标允许权衡，事前定义；不能看完结果再改标准。

稀疏或部分标签中，unknown与可靠负例分开。评估器计为FP不自动赋予训练负标签；教师预测也是软目标而非新GT。

在预算允许且有收益信号时，用独立组/折、扰动敏感性或种子检查稳定性。组数很少时报告限制，不能对相关帧/边自助采样制造置信度。用户只授权单seed时遵守，不擅自增加。

## 防止无收益循环

事前给方向设一个适合预算的复审节点和停止条件，不硬编码所有比赛统一试验次数。以下证据应触发方向重评：

- 监督子集近乎饱和，真正困难的竞争缺标签或特征。
- 损失/置信度变化明显，但排序、召回、候选覆盖或最终决策没有稳定收益。
- 改善反复被后续模块抹去，或只来自坐标重匹配/节点数量而非预期机制。
- 本地与榜单排序多次不一致，或收益只来自单一组。

下一步可以是换信息来源、改变可学习任务/接入位置、更新基座、修复验证或结束方向。不要默认追加层数、KL系数、seed、倍率或再次做同类诊断。诊断必须能改变决策；若现有证据已足以执行授权的小规模验证，就执行。

刷新开源基座与相关研究的时机包括：进入新方向、已有公开更新、出现平台期和最终选择前。核实原始代码、实际启用分支、精确版本成绩、发布时间与训练暴露；不追随标题分数，不把赛后资料当作赛时可得证据。

## 执行与收束

遵守项目指定环境和资源。长任务保存命令、配置、PID、输出/错误日志和新输出目录；按项目要求做一次启动检查后返回，不自动监控或重跑。先检查重复任务。无明确授权不清理或覆盖历史实验。

区分 `implemented → prechecked → running → evaluated → packaged → pushed → remote_complete → submitted → scored`。每次只报告实际达到的状态；推送运行不等于比赛提交。skill本身不授予训练、上传、提交、发消息或自动监控权限。

结果汇报回答：改了什么、数据实际消费多少、实现核验是否通过、最终/分组指标怎样、证据支持什么和不支持什么、下一步明确决定。持续保留最佳有效候选与可回退版本，不因最新运行完成就自动晋级。
